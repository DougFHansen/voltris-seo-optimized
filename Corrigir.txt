OBJETIVO

Faça uma AUDITORIA DE SEGURANÇA PROFUNDA no meu projeto Next.js + Supabase + Vercel.

1. METODOLOGIA DE RED TEAM
━━━━━━━━━━━━━━━━━━━━━━

Para cada funcionalidade, pense nas seguintes perguntas:

1. O que um usuário não autenticado consegue fazer?
2. O que um usuário autenticado consegue fazer?
3. O que um usuário comum consegue fazer que deveria ser permitido apenas a administradores?
4. É possível manipular IDs, UUIDs, parâmetros ou cookies para acessar recursos de outro usuário?
5. É possível chamar APIs diretamente sem passar pela interface?
6. É possível modificar requests manualmente para contornar validações?
7. Existem endpoints que confiam excessivamente no frontend?
8. Existem verificações de autorização somente no cliente?
9. Existem Server Actions que podem ser chamadas diretamente?
10. Existem API Routes sem autenticação adequada?
11. Existem endpoints sem rate limiting?
12. Existem diferenças entre autorização no frontend e backend?
13. Existem objetos que podem ser acessados através de IDOR/BOLA?
14. É possível escalar privilégios?
15. É possível acessar dados de outros usuários?
16. É possível modificar dados de outros usuários?
17. É possível executar operações administrativas como usuário comum?
18. Existe algum segredo, token ou chave exposto?
19. Existem informações sensíveis nos bundles JavaScript?
20. Existem mensagens de erro que revelam informações internas?

Não presuma que a interface impede uma ação.

Considere sempre que o atacante pode ignorar completamente o frontend e enviar requests diretamente para os endpoints.
